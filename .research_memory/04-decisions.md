### 2026-06-15：方向最终锁定——过程监督 RL for Agentic RAG（接受做 RL，以 ReasonRAG + ProRAG 为 baseline）

- **背景**：用户连续否掉若干方案后（DocRE→agent项目→PRM/verifier→tool-use SFT），自己找来两篇要求当 baseline。AI 读后指出**两篇都是 RL**，与用户先前"不想搞 RL"冲突；用户明确回复"**接受，搞 RL 吧**"。
- **两篇 baseline**：
  - **ReasonRAG** (arXiv:2505.14069, NeurIPS 2025, 华为诺亚+港城大)：agentic RAG 过程级奖励；自建 RAG-ProGuide 数据集（query 生成/证据抽取/答案生成三段过程奖励）；过程监督 policy optimization；5k 数据超 Search-R1 90k。开源代码 `Applied-Machine-Learning-Lab/ReasonRAG`。
  - **ProRAG** (arXiv:2601.21912, 2026, 人大 Dou 组)：过程监督 RL for RAG；MCTS 造 PRM + 双粒度 advantage（step 过程奖励 + 全局结果奖励聚合）；开源代码+模型 `lilinwz/ProRAG`。
- **决定**：毕业论文方向 = **过程监督强化学习 for Agentic RAG**，在上述两篇基础上做。**接受 RL**（推翻 2026-06-10 的"不做 RL"约束）。
- **理由**：① 比 agent-PRM 稀疏 niche 脚手架足（agentic RAG 成熟，Search-R1/R1-Searcher 一堆可抄，不易卡死）；② 保留"过程奖励"的硬核不水；③ 两篇都开源、2025/2026 达标。
- **已知风险/待解**：① RL 比 LoRA SFT 重（retriever+rollout+RL loop，8×3090 跑 7B 可行但工作量大）；② **ProRAG(2026) 已沿 ReasonRAG 线又推一步，两篇白区在收窄**——必须找到 ProRAG 未覆盖的角度，否则被说"和 ProRAG 雷同"。下一步精读两篇定白区。
- **环境**：8×3090 仍是 GPU 执行环境（待用户最终确认可用性）。

### 2026-06-10（同日，晚些）：方向改判——从"PRM/verifier"改为"tool-use 函数调用"（纯按能毕业）

- **背景**：AI 先推荐"步骤级过程奖励/verifier"，理由含"吃老本行(训模型)"+"职业/导师对口"+"做的人少=不水"。用户连续戳穿：
  1. **用户没训过模型**——B 会的训练(PCE 检索器)是师姐做的，用户只调了 AIM(attention，提升 +0.2)。**没有"训模型"老本行。**
  2. **明确要求不考虑"职业/导师对口"**，只论"做啥能毕业"。
  3. 隐含戳中"做的人少"的矛盾。
- **AI 自我纠正（关键认知修正）**：
  1. "做的人少=好" 是**发论文逻辑**；对"只求毕业"是**坏事**（能抄的代码/基线少 → 易卡死 → 毕业头号风险是"做不出来"，不是"被说水"）。
  2. **硕士毕业的"不水" ≠ 全球新颖**，而是"方法+数字+对比+消融+错误分析"。→ **成熟拥挤、脚手架多的方向对"只求毕业"反而更安全。**
  3. 用户没训练经验 + PRM 方向稀疏 + 需训模型 = 最差组合。**撤回 PRM/verifier 主线。**
- **决定（用户拍板"就这么做"）**：主线改为 **tool-use / 函数调用可靠性**，**LoRA 微调开源模型**（最易学的训练，不碰 RL），在 **BFCL** 榜上做；挑 BFCL V4 承认的弱点（多轮 / 错误恢复 / 格式敏感）做可量化改进。
- **取舍**：用"低毕业风险"换"方向稀缺性/逼格"。硕士足够。
- **资产处理**：PRM/归因那批 PDF（`papers/` 根目录）保留作兜底/相关工作，不删。tool-use 相关工作单独存 `papers/tool-use/`。

### 2026-06-10：重大转向——导师建议弃 DocRE/EE，改做"航天科工指控系统 agent 自演进"项目方向

- **"会不会水"的分界线**（硕士答辩口径）：水 = 纯 prompt+编流程+demo、无量化评测；不水 = 有**训练/学习组件** + benchmark + baseline 对比 + 消融 + error analysis。用户 B 会"训模型（对比学习检索器）"的经验正是反水资产。

- **决定**：
  1. **方向转向这个 agent 项目，倾向研究内容二**。DocRE/TTM-RE（C' 方案）**暂停（不删，作兜底）**。
  2. **研究内容二不依赖指控真实数据**——有公开 benchmark（Who&When、ProcessBench、AgentProcessBench、PRM800K），所以"数据 unknown"不卡主线。

  4. **兜底**：verifier 打不过基线→框架+error analysis 仍能凑硕论；嫌太硬→退研究内容一（要素抽取，最贴 RE/EE 老本行）。

### 2026-05-27（同日 N+1）：arxiv 真实数据修正——DocRE 是"冷门活着"而非"甜区"

- **背景**：用户质疑 N 轮里"DocRE 13 篇/年 vs EAE 7 篇/年"的数据来源，且问有没有 arxiv 调研

  - EAE arxiv title 累计 46 / 2025 全年 2 / 2026 前 5 月 1 / 2024 11
  - RAG arxiv title 累计 1,522 / 月产 ~60 → 年 ~700
  - ICL arxiv title 累计 2,067 / 月产 ~70 → 年 ~840
- **修正之前的 framing**：
  - 我之前用 "DocRE 13 vs EAE 7" 论证"DocRE 是甜区"——**口径混乱、不能相比**
  - 真实对比：**DocRE 2025 是 EAE 的 3.5x**（7:2，arxiv 严格 title），但都是个位/十位数
  - **DocRE 比 RAG/ICL 冷 30-40 倍**，是冷门子方向，不是热点
- **对老师"过时"担忧的修正回答**：
  - "过时"严格说不对——DocRE 还在顶会主会出（NAACL/COLING/EMNLP/EACL Main）

  - 不能再用"DocRE 比 EAE 多 2 倍所以活"这种话术——量级一致，差异是定性的不是定量的硬证据
- **新发现的 long-tail/few-shot 方向更拥挤**：

  - DOREMI（2026-01）、VaeDiff-DocRE（2025-01）、GLiDRE（2025-08）、AMTL（ACL Findings 2025）合起来已经覆盖 long-tail 的多个角度

### 2026-05-15：Y 改进点优先级修正——Y2/Y3（LLM 外挂）优先于 Y1/Y4（动 memory 内部）
- **背景**：精读 TTM-RE 后重新审视 4 个候选 Y。新发现 3 个事实：
  1. TTM-RE 真正的胜负手是"两段式 schedule + SSR-PU loss"，memory 模块只是配菜
  2. Human-only setting 下 TTM-RE 没赢 SSR-PU（79.95 vs 80.18）——TTM 优势只在 H+D 成立
  3. **DeBERTaV3 替 RoBERTa 反而掉 4 F1**（80.56 vs 84.01）——TTM 模块对 backbone 敏感
- **关键风险类比**：事实 3 跟用户 B 会 AIM 失败的根因（"换 backbone 大概率失效"）**是同类问题**
- **解耦判断**：
  - Y1（动 memory 内部，替换 nn.Parameter 为 retrieved tokens）/ Y4（在 memory 上加 InfoNCE）**跟 TTM 主体强耦合**，等于在作者代码上做手术——继承 backbone 敏感性风险
  - Y2（LLM verifier）/ Y3（LLM reranker）**完全外挂**，只读 TTM 输出的 top-K 候选——TTM 主体换什么 backbone 都不影响外挂
- **决定**：
  - **首选 Y2 或 Y3**（外挂式）
  - **Y1/Y4 降级为兜底**（如果 Y2/Y3 跑出来效果不行再回过头做）
- **理由**：用户已经在 B 会被"backbone 敏感"坑过一次（AIM +0.2 F1 且换模型失效），不能再栽同一个坑。外挂式改进的"涨分"独立于底座，是更干净的科研姿态
- **遗留待验证**（P0 复现完立即测）：Y2/Y3 的 LLM 推理成本——DocRED test ~1000 doc × 几十~上百候选三元组 = 万到十万级 LLM 调用，7B 在 3090 上可能要几小时到一天。意味着 ablation 数量受限，要先在 sample 子集上调
