# 项目规则

## 🚪 新会话第一动作（强制）

**第一轮回复之前，必须先读 `.research_memory/06-handoff.md`**，它是 agent 入口文件，5 分钟内拿到完整上下文。

然后按其中的"阅读顺序"章节读剩余的记忆库文件。

> 项目可能在多台机器之间跨机接续（Windows 笔记本 ↔ 实验室 Linux 服务器，通过 git 仓库 `git@github.com:bimuyuQvQ/Kaiti.git` 同步）。06-handoff.md 会告诉你在哪台机器上应该做什么。

## 研究记忆库（强制规则）

本项目存在长期研究记忆库 `.research_memory/`（相对于仓库根目录，因为跨机路径不同），包含 7 个 md 文件：

- `06-handoff.md` **⬅️ Agent 入口（新会话先读这个）**
- `00-context.md` 研究者背景、目标、约束、偏好
- `01-directions.md` 候选研究方向 + 可行性判断（已锁定方向置顶）
- `02-papers.md` 论文池（底座 TTM-RE + 候选清单 + 必读论文 + 引用数）
- `03-trends.md` 方法学趋势观察（注意顶部口径警告）
- `04-decisions.md` 关键决策日志（按时间倒序）
- `05-next-steps.md` 当前待办与下次切入点

### 会话开始时必做

每次新会话的第一轮回复**之前**，必须先读 `.research_memory/06-handoff.md` 和 README，再按 handoff 指示读其余文件。

### 每轮对话结束前必做（自检清单）

每轮在回复用户**之前**自问：

1. 用户表达了新的偏好/约束/目标？ → 改 `00-context.md`
2. 讨论了新研究方向 / 推翻了旧判断？ → 改 `01-directions.md`
3. 出现新论文 / 论文被下载/读过 / 拿到新引用数？ → 改 `02-papers.md`
4. 形成了新的横向趋势判断？ → 改 `03-trends.md`
5. 做了"选 A 不选 B"、"放弃 X"类的决策？ → 追加到 `04-decisions.md`
6. 本轮结束时有未完成的 next step？ → 刷新 `05-next-steps.md`

命中任一就更新对应文件。**用户不需要主动提醒，AI 自动决策**。

如果本轮纯闲聊或纯解释、没有新结论，则不更新。

### 写作约定

- 时间戳使用 `YYYY-MM-DD` 格式
- 论文统一使用：`论文简称 (arXiv:xxxx.xxxxx)`
- 引用数标明来源：`[OA: N]` 或 `[SS: N]`
- 决策日志条目格式见 `.research_memory/README.md`

## 编码与沟通规则（来自用户）

- 中文回复
- 不假设用户清楚自己想要什么 → 动机不清晰时停下来讨论
- 目标清晰但路径不是最短的，直接告诉用户并建议更好的办法
- 遇到问题追根因，不打补丁
- 输出说重点，砍掉一切不改变决策的信息
- **拒绝代码占位符**（`YOUR_API_KEY` / `<base_url>` 之类）
- 需要环境/配置值时**主动用 AskUserQuestion 工具询问**
- **高危操作（修改/删除现有数据）必须明确说明计划等待批准**
- 预期长时间执行的命令**不能阻塞对话**：要么后台跑，要么明确告诉用户在干什么
